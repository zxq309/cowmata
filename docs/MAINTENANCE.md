# 四仓维护约定

总体仓维护项目范围、路线图和组件组合。组件仓维护自身代码、接口说明、测试、变更记录和发布版本。
标注或识别问题在对应仓处理；融合与辅助证据在决策仓处理；跨仓问题在总体仓记录并链接对应修改。

每个仓独立提交和版本发布，版本号不要求同步。总体 components.json 记录固定 commit 和兼容验证状态，禁止使用“最新版”代替可追溯版本。
先验证组件，再验证跨仓数据样例；验证过的组合才标记兼容。原始数据、模型、标签协议各自记录版本。
包源码只在所属仓维护；标注工具以适配层调用算法，尽量减少推理实现复制。

公开仓只展示已核实的能力边界。决策实验细节保留私有仓；成员无法访问私有链接时不会影响公开组件独立使用。
原算法仓与标注仓保留名称及提交历史，本次调整以职责说明和跨仓入口为主。
